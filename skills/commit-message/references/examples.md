# 提交信息正反例对照

本项目历史提交里提炼出来的对照。左边是初稿常见写法，右边是改进后的。

## 例一：修 bug

**初稿**

```
修复输出截断的 bug
```

问题：哪个 bug？什么症状？怎么修的？三个都没说。

**改进**

```
输出截断改为等管道空闲，而非从 exit 起算固定时限

症状：命令输出 3000 行，只收到 863 行，无任何报错。

根因是短命的主进程 exit 后，它 fork 出的后台进程还持着 stdout 继续写。
按固定时限关流会静默丢掉那些输出 —— 丢的通常正是错误信息。

改成记录 last_data_at 轮询判断：还在来数据就继续等，真的静默了
grace 秒才放弃。
```

## 例二：加功能

**初稿**

```
添加 load_skill 和 load_skill_file 工具
```

问题：复述了 diff。为什么需要两个工具、为什么不用现成的 read_file 都没说。

**改进**

```
技能加载走专用工具，不复用 read_file

让模型自己用 read_file 读 SKILL.md 不可靠 —— 它经常不读。专用工具的
调用是显式的、可观测的，前端能显示"正在加载技能 X"。

分两个工具是因为 L2（正文）和 L3（附件）的调用频率差一个量级：正文
一次就够，附件可能要读好几个。合成一个工具的话参数会变成互斥的可选项，
模型容易搞错。
```

## 例三：重构

**初稿**

```
优化了技能加载的性能
```

问题："优化"没有数据支撑，读者无法判断值不值得。

**改进**

```
技能扫描遇 SKILL.md 即停止递归

原来用 rglob 全量遍历。技能自带的 references/ 里如果有示例 SKILL.md
（技能作者演示用），会被当成一个真技能加载进来。

顺带跳过 node_modules 和 .git —— 技能目录里放了依赖时，原来会遍历整棵树。
```

## 例四：纯格式调整

不要编造动机。直接说明是格式调整：

```
统一 skill 模块的 import 顺序

ruff --fix 的结果，无行为变化。
```
